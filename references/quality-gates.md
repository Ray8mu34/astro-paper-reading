# 阅读质量与执行质量分开验收

## 先实际读文章

1. 前几分钟能说明问题、困难、思路/贡献、主要结果和科学范围吗？
2. 导览是否对应原文每个主要§，职责与关键图表是否准确，PDF页入口是否可用？
3. 正文段落是否推进科学理解，执行/覆盖/工具信息是否进入独立notes？不要用关键词禁令代替判断。
4. 深讲主题是否自然回应概览，核心推理和必要长推导是否完整？
5. 每幅图是否有教学理由，原图承载什么证据，交互增加什么理解？删除无增益图。
6. 改变结论的先验、简并、标定/模型条件是否在相关讨论处可见？

人工保存上述对照结果到validation或comparison，既评估开头也阅读推导。不要以正文缩短比例或自动检查数量评分。

## 执行检查

从Skill目录用项目解释器运行scripts/validate_skill.py；新实例加--analysis FILE --require-artifacts，从当前资产确定性检查三个产物。更改schema/renderer时运行pytest；改数值模块或数据才重跑相关数值检验，不无故重算已有几何。

实际离线打开HTML，确认选择的图形/控件有下游改变，错误和reset工作，正文地图链接、导航与附录可键盘操作。检查首屏、长推导、原图完整性及宽窄屏截图；无JS错不代表阅读体验良好。没有交互时不捏造控件测试；缺浏览器则保留未测状态。

元数据验证不能证明论文解读正确；来源定位需人工对照。无需每次阅读重跑整个安装/发布测试。独立Agent审读只在已获授权且实际执行时记录；本地作者复查不能标为独立外审。

记录命令/结果、当前资产与版本、复现范围、失败及未知在analysis-notes.md/validation中，正文只保留科学含义。代码/数据可随附，读者交付以报告入口为主。Git改动保持可评审；不修改无关数值代码。
