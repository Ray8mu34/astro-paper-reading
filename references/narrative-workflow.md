# 原文优先、按需深入的轻量工作流（天文学）

**默认原则**：作者按什么顺序提出科学问题、引入测量/假设、设计方法、展示结果并讨论解释，就按什么顺序带读。重点解释其中的逻辑关系，不先按模型自拟的“最短故事”洗牌；内部验收不应成为一篇论文的第二项研究工程。

## 1. 顺原文章序建立一次章节地图

固定主文/预印本版本，阅读实际 PDF 的主要章节、必要图表/图注、公式及关键附录。从论文实际目录依序填 `reader.roadmap`：`section` 原文编号、`title`、`argument`（该节要解决什么论证问题）、`focus`（关键图/式/表）、`source_id`、`page`。阅读时顺手记录章节的前因后果即可，不必第二轮重做理解计划。

- **观测与数据论文**：作者怎样提出待测问题或待检验解释，为什么选这个目标/样本与仪器，如何从原始观测得到可用测量，模型与假设在哪里进入，结果如何支持物理结论。
- **理论论文**：为什么研究这个命题，关键假设和定义如何引入，中间的近似、演算或证明各解决什么，哪些结论可以转化为可检验预言。
- **模拟论文**：目标物理现象、控制方程、初始/边界与数值设置为何如此选择，结果是否经过必要的收敛/极限检验，哪些是模型条件下的物理解释。
- **仪器与算法论文**：已有测量或计算瓶颈，方案如何针对限制，基准/实验怎样检验精度、灵敏度、系统误差或计算性能。

以上是识别论证职责的提示，**不是正文顺序的统一模板**。简述不影响贡献的文献罗列或标准流程，但不能跳过促成作者技术选择的比较。涉及多条并行证据时，保留论文的汇合点；任何额外因果解释都要与作者实际主张区分。

根据已记录的 `roadmap` 写一段前置的 `reader.argument_route`，让初读者知道论文如何逐节推进；`reader.overview` 概述科学对象、主要方法和结果。`throughline/connections` 仅复杂依赖时可选，普通任务不生成重复的每节 `needs/adds` 账本。

## 2. 正文以原章序讲解，技术在对应位置加深

默认 `reader.organization="paper-order"`，各主文节写 `sections[].source_sections`，与实际 `roadmap.section` 标签一致。正文主要章节需覆盖 `roadmap` 且顺序不颠倒；允许相邻短章合讲或一个重点章连续拆讲，但每章的问题、方法、证据不能只留在后置目录中。正常不要求逐段翻译、复写附录或平均分配章节篇幅。

每一节自然交代：上一节得到了什么，还缺什么；本节作者为何采取这项测量、假设、方法或检验；核心物理/数学如何工作；这一步给后文留下了什么。复杂公式应出现在读者知道其作用之后；局部前置一个量纲关系、符号或直观例子是解释桥梁，不等于重排原文。

原图、光变、谱、CMD、误差图、后验、分辨率/收敛图与模拟截面应放在原本回答的问题旁。每图解释坐标、单位、测量与模型身份、比较条件、主要特征；不以文字摘录数值代替关键原图。没有原图可用则据实描述，绝不伪造。

真正影响当前结论的条件（例如时间系统、坐标、光度标定、selection function、prior、参数简并、模拟边界和近似阶数）就在该处解释一次。可讨论作者未验证的替代解释，但应在作者主要论证完成后集中进行，不把批判审查插入每一段。独立评价节可以不映射源章节，其角色应标明 review/limitations。

程序只校验已填写的 roadmap 和正文的映射关系；作者仍需对照实际论文确认未漏章。用户明确要求专题重组或原文顺序确实不可解时，设置 `restructured` 并给具体 `departure_reason`；完整主要章覆盖仍必须保留。

## 3. 仅一次合并式检查

结束时对照原文目录及报告：主要章是否覆盖且次序正确，作者的问题/技术选择理由是否清楚，关键公式、单位、主要原图和结论是否准确，独立分析是否晚于完整作者论证，报告是否构建成功。只改确实出现的错误。不要为了验证再次生成论文复述、模拟首次读者、填写人工读者测试表或跑数值/浏览器整套回归。普通交付仅运行：

```sh
python scripts/build_report.py --analysis WORK/analysis.json
python scripts/validate_skill.py --analysis WORK/analysis.json --require-artifacts
```

Markdown-only 两条命令加 `--md-only`。pytest/发布/浏览器检查仅服务 Skill 开发或明确的专项需求；不参与每篇论文的阅读流程。
