# 天文图形：尊重原文论证位置，优先关键证据

每幅图先判断要解释哪一个真实的科学难点：原论文图与准确文字是否已足够？如已足够，不另造示意或交互。`visuals` 记录必要的来源/图形类型/放置位置与选择理由，不需要为了每节填图形清单。`interactive-html` 允许零交互。

## 原图优先并放回原文章节

在作者使用图表构造测量/说明机制/支持结论的位置，优先呈现**完整框架图、重要光变或光谱、CMD、空间分布图、后验、残差、模拟对比或数值收敛图**。解释原图的坐标、单位、波段、时间尺度、色标、样本、观测/模型身份、误差与关键分支，指出读者应观察什么，以及该特征实际支持作者哪条科学论断。保留决定比较的轴和子图，不只抽出一串数字。图可能包含上限、censored 点、非均匀采样或物理尺度，应如实解读。

原图不能访问时可以精确文字说明，不把想象中的测光点、合成谱或随机模拟充当作者实验。必要教学示意标注 schematic、independent calculation、synthetic 等，不与作者报告或真实观测混称。对于巨大参数表可抽出核心比较，但保留条件和误差定义。

## 交互只为真实理解增益

在物理关系特别适合反事实探索时，可以通过改变 $s/q/\rho$ 查看焦散或有限源影响、改变先验观察条件后验、调整模拟视角观察投影；前提是**科学计算真实对应控件所称关系**、适用域与归一化清楚，数据来源可靠。静态图或原图已经足够时，不开发组件。不能为了使用已有微透镜库、打卡 UI 检查或让网页显得复杂而添加控件。

图形数据须保持参考系、坐标原点、角/物理尺度、观测误差、颜色映射与归一化一致。原作者模型、实际观测、独立计算及教学示意分开。科学边界在图注简要说明一次；版本、数值容差、seed、求解器残差、脚本与资产哈希记在技术记录，不在正文堆日志。

复用离线 `assets`、MathML、PNG/JPEG/WebP 或本地 HTML/CSS/JS/JSON manifest。确实修改了带物理计算的新交互时核对科学输出和操作行为；普通论文使用既有组件时不运行整套数值、浏览器与响应式回归。内置单/二元透镜组件只为微透镜相关任务服务，不宣称能计算未实现的拟合或光变模型。
