# Astro Paper Reading — original-paper order, lightweight workflow (v1.2.0)

This Skill teaches astronomy and astrophysics papers to graduate readers **following the authors' actual section order and scientific argument**. Reconstruct the paper's original main sections and their functions first. Explain why each observing choice, physical assumption, method, calculation or test appears where it does. Treat the authors' organization as a substantive part of the scientific argument, not a structure to discard in favor of a new story.

Use schema 1.3 for new reports: `reader.roadmap` reflects actual numbered sections, `reader.argument_route` briefly introduces the author’s argument near the start, and `sections[].source_sections` maps each reader section to the original. Default `reader.organization="paper-order"`. When a specific exception is necessary, use `restructured` with a concrete `departure_reason` while retaining section coverage. `reader.throughline/connections` are optional notes; do not create a duplicate step-by-step self-test or narrative ledger. Schemas 1.0 and 1.1 remain buildable.

In observational work distinguish measured quantities, calibration, fitted parameters, model-dependent physical interpretation, priors and selection effects. In theory work track definitions, assumptions, derivations and limits. In simulations track equations, initial/boundary conditions, numeric validation and physical interpretation. Keep key original figures at the chapter where the paper uses them and explain axes, units, models, uncertainties and decisive comparisons. Explain equations only once the reader knows why they are needed; deepen mathematics in that same section.

First reconstruct the authors' main argument and conclusions, then give a concentrated independent evaluation. Include real conclusion-changing qualifications at the relevant result once, not repeated defensive disclaimers. Preserve provenance and internal execution notes outside the reader-facing article. Do not invent author intent, failed experiments, observational data or calculations.

Routine production: **read → map source sections → write in paper order → build → one integrated check → deliver**. Do not require interim comprehension pauses, chapter-by-chapter retelling, `reader-review.json`, multi-agent cold reads, full dataset downloads, MCMC refits, pytest, browser/responsive UI testing or release checks unless the user explicitly requests the relevant task or the related software is being changed.
