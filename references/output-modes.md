# 四种用途，两个内容层

analysis.json 是共享科学状态。读者产物是 report.md/report.html；analysis-notes.md 与 validation/ 是内部证据、覆盖、参数、执行与复现记录。构建器不会自动将内部状态全部排进正文。

|模式|读者目的|组织方式|
|---|---|---|
|quick|决定值不值得读|具体问题、贡献、结果及范围，简短原文阅读入口；摘要级任务简洁标明材料级别|
|deep-md|理解中心论证及难点|研究概览、真实§结构导览、按概念依赖选择的深讲主题、必要科学评价及补充推导|
|interactive-html|阅读科学解释并探索有价值反事实|保持deep内容；原图/交互按教学理由选用，可零交互；离线界面是文章|
|critical-review|判断结论的稳健性|仍先建立问题/主张/原文地图，再集中审查假设、证据、替代解释与可区分检验|

不将 quick 换标题称 deep，不强制每个深读有长数学，不强制网页有图或固定数量控件。复杂推导允许足够长；选择原则不是删字而是删掉不推进中心理解的信息。

新状态1.1以reader.overview/roadmap/focus记录写作意图，sections按reader/appendix/internal区分受众。不同模式共享事实，但其文章应由作者按用途组织；模式过滤仅省略quick的补充推导，不能自动把完整文章变成好摘要。

来源版本、覆盖、工具能力、原数据是否取得和实际测试都完整记录在内部产物。改变科学结论的先验、简并、标定问题在正文说明一次，并在相关证据处定位。最终交付给阅读入口、重要变化与必要边界；不要用验收清单充当文章。
